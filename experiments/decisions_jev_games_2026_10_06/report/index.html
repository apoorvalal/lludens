Decision models in repeated economic games

GPT-6 Luna through OpenAI’s Decisions API and TypeSafe’s Jev 1.13.0 play simultaneous, twenty-round Prisoner’s Dilemma, Stag Hunt, and two-player public-goods games. The comparison separates the APIs’ selected actions from an explicitly randomized policy built from their returned probabilities.

Main finding. Jev earns slightly more in all three direct-choice head-to-head panels, largely by avoiding Luna’s occasional cooperative or risky moves. This is not a stable overall ranking: sampling from the distributions reverses the payoff comparison in Prisoner’s Dilemma and public goods. Both models solve every known-opponent best-response check.

Game rules and incentives

Every player is told to maximize its own expected total match points, not its advantage over the opponent and not joint welfare. The complete history, fixed remaining horizon, and all payoff rules are available at every decision. There is no communication, punishment phase, side payment, or hidden preference parameter.

Contributions are 0, 2, 4, 6, 8, or 10. A pool multiplier of 1.6 is shared equally. Own points: 10 − own contribution + 0.8 × total contribution.

With the stated fixed horizon, standard complete-information backward induction selects defection in Prisoner’s Dilemma and zero contribution in public goods under common knowledge of rationality. The agents are not told that their counterpart satisfies those assumptions. Low cooperation here is therefore not itself evidence of misunderstanding. Stag Hunt instead has two pure stage-game equilibria.

Payoff understanding, history, and ordering

The known-opponent check supplies each possible opposing action in a one-round game. Its optimal response is calculated directly from the payoff function. The model selects among the same actions, tested in both forward and reverse option order. Separately, seven fixed histories in each game are queried forward, reversed, and identically repeated.

History matters. In the controlled Prisoner’s Dilemma probes, both models cooperate following five mutual-cooperation rounds, defect following mutual defection, and defect in the final round even after nineteen cooperative rounds. In Stag Hunt, both choose Stag after sustained Stag/Stag play but Hare after sustained Hare/Hare play. These are responses to supplied histories, not evidence of training or parameter updates.

A small but consequential order effect. Luna’s empty-history Stag Hunt choice changes from Stag to Hare when the options are reversed. Jev chooses Hare in both orders. Jev’s public-goods response after mutual full contribution changes from 0 to 10 on an identical repeat. The small diagnostic does not establish order invariance or deterministic behavior for either service.

Experimental design and limits

  • 84 matches, 1,680 rounds, 3,360 game decisions. Forty-eight primary head-to-head matches, twenty-four sampled-policy matches, and twelve self-play matches, plus 166 controlled diagnostic calls.
  • Same economic information. Both plugins receive identical instructions and the same role-adjusted state text. The model’s or opponent’s brand is never in the prompt. The existing lludens phase engine stages both moves before publishing either.
  • Independent calls with explicit memory. Neither API provides a conversational agent. The entire public action/payoff history is supplied each round. No private chain-of-thought, free-form negotiation, or cross-match memory is added.
  • Order control. Legal options are shuffled independently for each seat and round with a fixed seed. Paired seat swaps retain each seat’s schedule. The order of the payoff explanation itself is held fixed. This is not an exhaustive prompt-robustness study.
  • Full offline replay. Every stored prompt and option ordering is regenerated, and every action, sampled draw, and payoff is replayed from the exact recorded response. No live API calls are needed to recompute the results.
  • Exploratory scope. One payoff specification, one twenty-round horizon, one framing, no communication, and two decision models. A two-player public-goods game does not establish behavior in larger groups. Within-match payoff advantages are not a universal measure of model intelligence or social desirability.
Integration and execution notes

The local lludens checkout and all pre-existing edits were preserved. New work is on experiment/decisions-jev-games-2026-10-06. Both Simon Willison plugins are pinned to inspected Git commits in requirements.txt.

Initial setup exposed an expired local API-proxy certificate; it was renewed with the same key and identity without disabling TLS or changing host permissions. LLM 0.36’s lazy plugin registration required serialization before concurrent use. An overly strict probability-mass check interrupted eleven public-goods matches and one probe: Jev returns two-decimal probabilities whose sum can be 0.99 or 1.01. The adapter now accepts only deviations consistent with that rounding and normalizes relative mass for sampling. Raw responses remain unchanged.

Successful calls were checkpointed individually. Incomplete matches resumed from their exact earlier histories, including any already-selected but not-yet-published move. No API error became a default action. Twelve rejected validation responses were not retained by the initial strict adapter and required a new call; this small service-level replay limitation is recorded. All final planned matches and probes completed. Fifteen focused harness tests cover incentives, simultaneous information, role perspective, schema validation, sampling, and failure handling.
